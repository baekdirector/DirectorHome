# 동사 3단변화 단어장 설계

## 배경 및 목표

JunsVoca는 지금까지 "영단어 ↔ 뜻" 한 쌍을 묻는 단어장만 다뤘다. 여기에 **불규칙동사의
3단변화를 묻는 단어장**을 더한다. 뜻("오다")을 보여주고 현재형·과거형·과거분사형 세 칸을
입력받아 채점한다.

쓰는 사람은 자녀이고, 외워야 할 92개 불규칙동사를 변화 유형별로 나눠 한 패턴씩 익히는 것이
목적이다. 성공 기준은 "유형별 단어장을 골라 시험을 보고, 세 칸 중 어디가 틀렸는지 바로
확인할 수 있다"이다.

## 범위

- `words`·`word_sets` 스키마 확장과 동사 단어장 종류 추가
- 뜻 → 현재·과거·과거분사 세 칸을 묻는 문제 유형과 채점
- 채점 결과에서 **틀린 칸만 짚어 보여주기**
- 변화 유형별 단어장 5개를 1회성 스크립트로 넣기
- 기존 단어장 입력 화면에 동사 형식 붙여넣기 추가

### 목표가 아닌 것 (Non-goals)

- **한 시험에 일반 단어와 동사 문제를 섞어 내기.** 동사 단어장은 목록에 함께 놓이고
  골라서 시험을 보되, 한 번의 시험은 한 종류만 다룬다.
- **칸별 부분 점수.** 세 칸을 모두 맞혀야 그 문항이 정답이다. 기존 정답률·오답노트가
  "문항 하나 = 단어 하나"를 전제하고 있어 그 전제를 지킨다.
- 현재형을 주고 나머지 둘만 묻는 역방향 출제. 이번에는 뜻 → 세 칸 한 방향만 낸다.
- 92개를 한 묶음으로 담은 "전체" 단어장. 유형별 5개로만 넣는다(아래 6절 참고).

## 1. 데이터 모델

기존 테이블을 확장한다. 새 테이블을 만들지 않는 이유가 설계의 핵심이다.

```sql
ALTER TABLE word_sets ADD COLUMN IF NOT EXISTS kind TEXT NOT NULL DEFAULT 'vocab';
-- kind: 'vocab' | 'verb'

ALTER TABLE words ADD COLUMN IF NOT EXISTS past TEXT;
ALTER TABLE words ADD COLUMN IF NOT EXISTS participle TEXT;
```

동사 단어장은 `kind='verb'`이고, 한 행이 동사 하나다. `term`에 현재형, `meaning`에 뜻,
`past`·`participle`에 나머지 두 형태를 담는다. 기존 행은 `kind='vocab'`, `past`/`participle`
이 NULL이라 손댈 것이 없다.

**새 테이블을 만들지 않는 이유.** `wrong_notes.word_id`는 `words(id)`를 참조하는 기본키이고,
`quiz_answers.word_id`와 정답률·시험 이력 질의가 모두 같은 id로 묶여 있다. 동사를 별도
테이블에 두면 오답노트·통계·이력이 두 갈래로 갈라져 전부 고쳐야 한다. 컬럼 두 개를 늘리는
비용이 그보다 훨씬 작다.

## 2. 복수 정답 형태

원본 데이터에 한 칸에 두 형태가 오는 경우가 있다 — `be`의 과거 `was/were`,
`get`의 과거분사 `got/gotten`, `show`의 `showed/shown`, `swell`의 `swelled/swollen`.

슬래시 형태를 **원문 그대로 저장**하고, 채점은 **슬래시로 나눈 것 중 하나만 맞아도 정답**으로
본다. 외우는 사람이 둘 다 알아야 하는 것은 맞지만, 한 칸에 하나만 받는 화면에서 둘 다
요구할 수는 없다. 정답 표시에는 저장된 원문(`got/gotten`)을 그대로 보여줘 다른 형태도
있다는 것을 알린다.

## 3. 문제 유형과 채점

`QuestionType`에 `'verb'`를 더한다. 기존 `'spelling' | 'meaning'`과 그 채점 함수
`checkAnswer(question, userAnswer)`는 **건드리지 않는다**.

동사 채점은 별도 순수 함수로 둔다:

```ts
export interface VerbAnswer {
  present: string
  past: string
  participle: string
}

export interface VerbResult {
  present: boolean
  past: boolean
  participle: boolean
  /** 세 칸이 모두 맞을 때만 참. 문항 단위 정답 여부다. */
  all: boolean
}

export function checkVerbAnswer(word: QuizWord, answer: VerbAnswer): VerbResult
```

칸별 비교는 기존 `normalizeAnswer`와 같은 규칙(앞뒤 공백 제거, 소문자화, 연속 공백 하나로)을
쓰고, 그 위에 슬래시 대체형 허용을 얹는다.

## 4. 시험 기록

`quiz_answers`는 스키마를 바꾸지 않는다. 문항당 한 줄을 쓰고:

- `question_type` = `'verb'`
- `correct_answer` = `come | came | come` (세 형태를 ` | `로 이음)
- `user_answer` = 입력한 세 칸을 같은 방식으로 이음
- `correct` = 세 칸 모두 맞을 때만 참

구분자로 `|`를 쓰는 이유는 **대체형이 `/`를 쓰기 때문**이다(`got/gotten`과 충돌하지 않는다).
이력·오답노트 화면은 `question_type`을 보고 `|`로 갈라 칸별로 보여준다.

## 5. 입력 형식

기존 단어장 입력 화면(`/input`)에 **일반 / 동사 3단변화** 전환을 둔다. 동사 형식은 한 줄에:

```
번호 현재형 과거형 과거분사형 뜻
```

번호는 생략할 수 있고, 구분자는 공백·탭·쉼표 모두 받는다(기존 파서와 같은 관례).
앞의 세 토큰이 변화형이고 **그 뒤 전부가 뜻**이다. 그래서 뜻에 띄어쓰기나 쉼표가 들어가도
(`눕히다, 놓다`, `비용이 들다`) 문제가 없다. 변화형 자체에는 공백이 없고, 대체형은
`was/were`처럼 슬래시로 붙어 있어 토큰 하나로 읽힌다.

읽지 못한 줄은 기존 입력 화면과 같이 따로 모아 보여준다.

## 6. 유형별 단어장

92개를 변화 유형별로 나눠 **5개 단어장**으로 넣는다. 한 패턴씩 익히는 편이 자연스럽고
시험도 유형 단위로 볼 수 있다.

| 단어장 | 유형 | 개수 |
|---|---|---|
| 동사 3단변화 · A-B-B | 과거와 과거분사가 같음 | 40 |
| 동사 3단변화 · A-B-C | 셋이 모두 다름 | 39 |
| 동사 3단변화 · A-A-A | 셋이 모두 같음 | 9 |
| 동사 3단변화 · A-B-A | 현재와 과거분사가 같음 | 3 |
| 동사 3단변화 · A-A-B | 현재와 과거가 같음 | 1 |

92개를 한 묶음으로 담은 "전체" 단어장은 만들지 않는다. 같은 동사가 두 단어장에 들어가면
`word_id`가 달라져 오답노트와 정답률이 따로 쌓이고, 한 쪽에서 틀린 것이 다른 쪽에 보이지
않는다. 여러 유형을 한 번에 보고 싶다는 요구가 생기면 "여러 단어장 골라 시험 보기"로
푸는 편이 맞다.

## 7. 화면

**단어장 목록(`/wordsets`)** — 동사 단어장에 배지를 붙여 구분한다. 나머지는 그대로다.

**시험 화면(`/quiz/:wordSetId`)** — 단어장의 `kind`가 `'verb'`면 문제 영역이 달라진다.
뜻을 크게 보여주고 **현재형·과거형·과거분사형 세 칸**을 세로로 놓는다. 각 칸에 라벨을 둬서
무엇을 쓰는 칸인지 분명히 한다. 제출하면 **맞은 칸은 그대로, 틀린 칸은 빨간 테두리와 함께
정답을 아래에 보여준다**.

진행 방식은 기존 시험과 같다. 틀려도 그 자리에서 막히지 않고 다음 문제로 넘어가며, 틀린
문항은 **전부 맞을 때까지 반복 라운드에서 다시 출제된다**.

좁은 화면이 주 사용 환경이므로 세 칸을 세로로 쌓는다. 엔터를 누르면 다음 칸으로 가고,
마지막 칸에서 엔터를 누르면 제출된다.

**오답노트·통계** — `word_id`로 묶이므로 코드를 바꾸지 않아도 동작한다. 다만 오답노트가
단어를 보여줄 때 동사 문항은 세 형태를 함께 보여준다.

## 8. 에러 처리

- 붙여넣기에서 토큰이 셋에 못 미치는 줄은 건너뛰고 "읽지 못한 줄"로 모아 보여준다.
- 한 단어장 안에 같은 현재형이 두 번 나오면 기존 파서와 같이 뒤엣것을 버린다. 단어장이
  다르면 서로 간섭하지 않는다(아래 참고).
- 세 칸 중 일부만 채우고 제출하면 빈 칸은 오답으로 본다. 빈 칸 경고를 따로 띄우지 않고,
  채점 결과에서 그 칸이 틀린 것으로 표시되며 반복 라운드에 다시 나온다.

**원본 데이터에 `get`이 두 번 있다.** A-B-B에 `get-got-got`, A-B-C에 `get-got-got/gotten`으로
들어가 있어 과거분사가 다르다. 교재마다 분류가 갈리는 동사라 둘 다 그대로 두되, 서로 다른
단어장에 들어가므로 각각 따로 외우고 따로 집계된다. 임포트할 때 이 사실을 출력해 알린다.

## 9. 테스트

순수 함수를 vitest로 덮는다.

**파서(`parseVerbLine`)** — 번호 있는 줄/없는 줄, 띄어쓰기 있는 뜻(`눕히다, 놓다`),
대체형이 든 줄(`be was/were been 이다`), 토큰이 모자란 줄, 탭·쉼표 구분.

**채점(`checkVerbAnswer`)** — 세 칸 모두 정답, 한 칸만 오답, 대소문자·앞뒤 공백 무시,
대체형 중 하나만 맞아도 정답(`got`·`gotten` 둘 다), 빈 칸은 오답.

**유형 분류(`verbPattern`)** — A-B-B/A-B-C/A-A-A/A-B-A/A-A-B 판정. 임포트 스크립트가
단어장을 나눌 때 쓰고, 분류 결과가 주신 개수(40/39/9/3/1)와 맞는지 확인한다.

화면은 실제 데이터로 로컬에서 확인한다(모바일 390px, PC 1440px).

## 10. 작업 순서

1. 파서·채점·유형 분류 순수 함수와 단위 테스트
2. 스키마 확장(`server/db.js`)
3. 92개를 유형별 5개 단어장으로 넣는 1회성 스크립트
4. API와 클라이언트 타입에 `kind`·`past`·`participle` 싣기
5. 시험 화면의 동사 문제 영역과 칸별 오답 표시
6. 단어장 목록 배지, 입력 화면의 동사 형식 전환
7. 오답노트 표시 보완
8. 로컬 확인 후 커밋·배포
