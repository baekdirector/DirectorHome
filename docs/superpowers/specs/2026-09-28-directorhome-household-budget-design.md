# DirectorHome 전환 + 가계부(지출관리) 서비스 설계

## 배경 및 목표

`JunsVoca`(자녀 영단어 학습 앱, React + Express + Postgres, Cloud Run 배포)를 `DirectorHome`이라는
가족용 우산 프로젝트로 확장한다. `DirectorHome`은 앞으로 여러 가족용 서비스를 담을 예정이며,
이번 스펙은 그 첫 번째 하위 프로젝트인 **가계부(월별 지출관리) 서비스**를 대상으로 한다.

기존에 스프레드시트(`매출이력`, 2021~2026년 시트)로 수기 관리하던 고정비·카드값·추가지출·
수입(월급/이자/입금)을 웹에서 월 단위로 입력하고, 연도별로 누적된 데이터를 통계로 볼 수 있게
만드는 것이 목표다.

자녀 학습(JunsVoca)과 가계부는 **같은 앱, 같은 배포** 안에서 공존한다. 기본 홈 화면은
지금처럼 학습 서비스이고, 가계부는 비밀번호로 보호된 별도 메뉴로 노출된다.

## 목표가 아닌 것 (Non-goals)

- 다중 사용자 계정/정식 로그인 시스템 (이번에는 비밀번호 팝업 하나로 충분)
- 커스텀 도메인 연결 (보유 도메인이 없어 이번 범위에서 제외, 추후 별도 진행)
- 건별(날짜별) 거래 입력 — 이번엔 시트처럼 "카테고리 × 월" 합계 입력만 지원
- JunsVoca 학습 기능 자체의 리브랜딩/UI 변경 (이번 스펙은 가계부 신규 구현과 앱 전체 리네이밍만 다룸)

## 1. 아키텍처

- 별도 서비스로 분리하지 않고, 기존 저장소(React SPA + Express + Postgres)를 그대로 확장한다.
  가계부는 새 React 라우트(`/household` 등)와 새 Express API 라우트, 새 Postgres 테이블로 추가된다.
- 배포는 지금처럼 Cloud Run 단일 서비스 1개로 유지한다(서비스 자체는 재생성, 아래 2번 참고).

## 2. 리브랜딩 (저장소 / Cloud Run / PWA)

이번에 한 번에 일괄 변경한다:

- **저장소명**: GitHub `baekdirector/JunsVoca` → `baekdirector/DirectorHome`, `package.json`의
  `name` 필드도 `directorhome`으로 변경.
- **Cloud Run 서비스**: Cloud Run은 서비스명을 그 자리에서 바꿀 수 없으므로(새로 만들고 옮기는 구조),
  `directorhome`이라는 새 Cloud Run 서비스를 새로 배포하고 `DATABASE_URL` 등 환경변수를 동일하게
  설정한 뒤 기존 `junsvoca-827177198889...run.app` 서비스는 삭제한다. **URL이 바뀌므로 자녀들이
  기존에 홈 화면에 설치해둔 PWA는 깨지고 재설치가 필요하다** — 사용자가 이를 감수하기로 확인함.
- **커스텀 도메인**: 보유 도메인이 없어 이번 범위에서는 진행하지 않는다. 새 Cloud Run 자동생성
  URL(`directorhome-xxxx.run.app` 형태)만 사용한다.
- **앱 이름/아이콘(PWA)**: 매니페스트의 앱 이름과 아이콘을 `DirectorHome` 브랜드로 교체한다
  (아래 8번 아이콘 디자인 참고). 학습 화면과 가계부 화면 모두 이 브랜드 아래에 있는 하나의 앱으로 노출된다.
- 이 리브랜딩 작업(저장소명, Cloud Run 재배포, 매니페스트 교체)은 가계부 기능 구현과 별개로
  먼저 처리 가능한 작업이며, 실제 Cloud Run 리소스 생성/삭제와 GitHub 저장소 이름 변경은 로컬
  개발 환경에 `gcloud` CLI가 없어 사용자가 직접 실행해야 한다(구현 계획 단계에서 실행 커맨드를 정리한다).

## 3. 데이터 모델

**`household_categories`** — 지출/수입 항목 정의
- `id`, `name`(예: "삼성카드"), `group`(`fixed` 고정비 / `card` 카드 / `income` 수입 / `other` 기타),
  `sort_order`, `is_active`(비활성화된 카테고리는 목록에서 숨기되 과거 데이터는 유지)

**`household_entries`** — 월별 합계 값
- `id`, `year`, `month`, `category_id`, `amount`
- `(year, month, category_id)` 조합은 유일해야 하며, 같은 조합 재저장 시 upsert(덮어쓰기)

카테고리는 화면에서 사용자가 직접 추가·삭제·순서변경할 수 있다(고정 목록 아님).

## 4. 입력 화면(UX)

- 연/월 선택 후, 활성 카테고리가 그룹(고정비/카드/수입/기타)별로 세로 목록으로 표시된다.
- 각 항목은 숫자 입력 필드 하나를 가지며, `inputmode="numeric"` 키패드 + 천단위 콤마 자동 포맷,
  탭 시 전체 선택되어 바로 덮어쓰기 가능하다.
- **저장은 항목별 자동저장**: 입력 후 포커스를 벗어나면(blur) 즉시 서버에 저장된다. 별도 "저장" 버튼 없음.
- 카테고리 추가/삭제/순서변경 UI가 같은 화면(또는 별도 "카테고리 관리" 화면)에 존재한다.

## 5. 접근 제어 (비밀번호 팝업)

- 로그인 시스템이 아니라, "가계부" 메뉴 클릭 시 앱 디자인에 맞는 **커스텀 모달**이 뜬다
  (브라우저 기본 `alert`/`prompt` 사용 금지).
- 비밀번호는 서버 환경변수(`HOUSEHOLD_PASSWORD`)로 관리하고, 서버가 검증한다. 소스코드에
  평문으로 하드코딩하지 않는다.
- 통과 시 브라우저에 장기 유효 토큰(약 30일)을 저장해, 같은 기기에서는 매번 재입력하지 않는다.
- 오답 시 모달 안에서 인라인 에러만 표시(팝업 재중첩 없음).

## 6. 통계 화면

세 가지 차트를 제공한다:
1. **월별 추이 라인차트** — 선택 연도의 1~12월 추이, 카테고리(또는 그룹) 토글로 필터링
2. **카테고리별 비중 도넛차트** — 선택한 연/월 기준
3. **수입 vs 지출 흐름 비교** — 월급/이자/추가입금 합계 대 지출합계를 나란히 비교

차트 색상은 8번의 그룹 색상 체계(고정비=파인그린, 카드=클레이, 수입=골드)를 그대로 사용해
목록·차트·아이콘 전체에서 동일한 색상 의미를 유지한다. 세부 배색은 구현 시 `dataviz` 스킬
가이드를 따른다.

## 7. 과거 데이터 이전 (2021~2026)

- 기존 구글시트(`매출이력`, 연도별 탭)의 값을 1회성 마이그레이션 스크립트로 읽어
  `household_categories`/`household_entries`에 적재한다.
- 연도별로 시트 항목 구성이 조금씩 다를 수 있으므로, 마이그레이션 시점에 항목명을 정규화한다.
- 이 마이그레이션은 상시 기능이 아니라 1회 실행 후 제거 가능한 스크립트로 작성한다.

## 8. 비주얼 디자인 시스템 (가계부 모듈)

기존 앱의 크림 배경(`--color-bg: #faf7f0`)과 한글 폰트(Noto Sans KR)는 그대로 공유하되,
가계부 모듈만 "차분하고 신뢰감 있는 어른의 공간"이라는 인상을 주도록 별도 톤을 입힌다.
(자녀 학습 화면의 발랄한 테라코타/티얼 톤과 의도적으로 구분되는 것이 목적이다.)

**색상**
- Pine `#123A34` — 브랜드/고정비 그룹, 아이콘 배경색
- Clay `#A2432E` — 카드 그룹
- Gold `#B98A3D` — 수입 그룹 + 전체에서 딱 한 번씩 반복되는 포인트 도트(강조 모티프)
- 라벨/보조 텍스트 `#8a8674`, 구분선 `#eee7d6`

**타이포그래피**
- 세리프 사용 안 함(한글에 라틴 세리프를 섞으면 시스템 폴백으로 궁서체처럼 보이는 문제 확인됨).
  기존 `Noto Sans KR` 하나로 통일하되, 요약 숫자는 두꺼운 웨이트(800)로 키워 강조하고
  화폐 단위("원")는 더 가는 웨이트로 작게 붙여 대비를 준다. 금액은 `tabular-nums`로 자릿수 정렬.

**레이아웃**
- 카드형 그리드 대신 **장부형 리스트**: 각 항목은 왼쪽 3px 색상 바(그룹 색상) + 항목명 +
  오른쪽 정렬 금액, 얇은 구분선으로만 나눔 — 실제 가계부 장부를 웹으로 옮긴 인상을 준다.
- 화면 상단 "이번 달 요약" 패널만 화이트 서피스 + 상단 4px 골드 라인으로 유일하게 강조하고,
  나머지는 절제된 톤을 유지한다(과한 장식 지양, 강조는 한 곳에 집중).
- 통계 화면: 상단에 라인차트를 풀 너비로 배치, 하단에 도넛차트와 수입/지출 비교를 데스크톱은
  2열, 모바일은 세로 스택으로 배치.

**아이콘/앱 브랜딩**
- 둥근 사각형 아이콘, Pine(`#123A34`) 배경에 크림색 미니멀 집 실루엣, 우측 상단에 작은
  Gold(`#B98A3D`) 포인트 도트 하나. PWA 앱 이름은 "DirectorHome"으로 교체.
- 이 아이콘/색상 체계는 가계부 모듈뿐 아니라 앱 전체의 새 브랜드 아이덴티티로 사용된다.

실제 구현 시 각 화면(입력/통계/비밀번호 모달)의 세부 디자인은 `frontend-design` 스킬 가이드를
따라 다듬는다.

## 미해결 사항 / 후속 작업

- Cloud Run 신규 서비스 생성·이전과 GitHub 저장소 리네임은 `gcloud`/GitHub 접근 권한이 있는
  환경(사용자 본인)에서 실행해야 한다 — 구현 계획에 실행 커맨드를 정리한다.
- 구글시트 연도별 탭의 실제 항목 구성 차이는 마이그레이션 스크립트 작성 시점에 다시 확인한다.
- 향후 JunsVoca 학습 서비스를 `DirectorHome` 우산 아래로 더 깊이 통합(예: 공통 네비게이션 개편)
  하는 작업은 이번 스펙 범위 밖이며 별도로 브레인스토밍한다.
