# 매일 숙제 (Daily Homework) 설계

## 1. 왜 만드는가

아이가 스스로 단어 테스트를 시작하지 않는다. 앱에 단어장이 17개 쌓여 있어도 무엇을
풀어야 할지 고르는 일 자체가 장벽이다.

부모가 미리 "이 날엔 이걸 풀어라"를 정해두면, 아이는 홈 화면에서 고민 없이 숙제 카드를
눌러 바로 시작한다. 성공은 **아이가 홈 화면을 열었을 때 할 일이 하나로 정해져 있는 것**이고,
부모가 **무엇이 끝났고 무엇이 밀렸는지 한눈에 보는 것**이다.

## 2. 범위

**하는 것**

- 부모용 `/admin` 화면: 단어장을 골라 날짜에 숙제를 배정하고, 배정 현황을 보고, 지운다
- 아이 홈 화면에 오늘 숙제와 밀린 숙제를 표시
- 숙제를 누르면 설정 화면 없이 바로 시험 시작
- 틀린 단어가 0이 되는 라운드를 마치면 숙제 완료로 기록

**하지 않는 것 (지금은)**

- 밀린 숙제 개수 제한, 알림/푸시, 숙제 수정(지우고 다시 낸다), 보상·스티커
- 아이별 구분 (지금 앱은 한 아이용이다)
- 숙제 전용 통계 화면 (기존 부모 리포트로 충분하다)

## 3. 핵심 결정과 그 이유

### 3.1 숙제는 날짜마다 한 행

기간 배정은 서버가 **날짜별 행으로 펼쳐서** 저장한다. 기간을 규칙 한 줄로 저장하지 않는다.

하루치만 지우거나 완료를 찍는 일이 이 기능의 일상이고, 규칙으로 저장하면 "이 날만 빼기"를
위해 예외 개념이 또 필요해진다. 하루 한 줄이므로 데이터량은 무시해도 된다.

### 3.2 완료는 숙제 행에 직접 기록한다

완료를 기존 `quiz_sessions`에서 추론하지 않는다. 추론하면 **밀린 숙제가 7개 쌓였을 때
한 번만 풀어도 7개가 전부 완료 처리된다.** 같은 단어장을 매일 배정하는 것이 이 기능의
핵심 사용법이라 이 구멍은 치명적이다.

숙제 카드가 자기 번호를 들고 퀴즈로 넘어가고, 퀴즈가 끝날 때 그 번호로 완료를 기록한다.

따라오는 결과: **아이가 숙제가 아니라 "테스트 시작하기"로 같은 단어장을 다 맞혀도 숙제는
완료되지 않는다.** 숙제 카드로 들어가야 찍힌다. 의도한 동작이다 — 숙제를 했다는 사실을
기록하는 것이 목적이기 때문이다.

### 3.3 "오늘"은 아이 폰이 정한다

서버(Cloud Run)는 UTC로 돈다. 날짜를 시각(epoch)으로 저장하고 서버에서 "오늘"을 계산하면
한국 시간 밤 9시 이후에 하루가 밀린다.

`due_date`를 시간대 없는 달력 날짜(`DATE`)로 저장하고, 클라이언트가 자기 지역 날짜를
`YYYY-MM-DD`로 만들어 `?today=` 로 보낸다. 서버는 그 문자열과 비교만 한다. 시간대 문제가
발생할 자리가 없어진다.

### 3.4 완료 기준은 "다 맞힐 때까지"

기존 복습 라운드를 그대로 쓴다. `Quiz.tsx`의 `finishRound`에 이미
`isFinal: wrongAnswers.length === 0`이 있고, 바로 그 지점에서 완료를 기록한다.

점수 기준(80% 등)을 쓰지 않는다. 기존 메커니즘을 재사용하는 쪽이 코드도 적고,
"다 맞힐 때까지 반복"은 아이가 이미 겪어 본 흐름이다.

### 3.5 단어장 목록은 배열 칼럼으로

`word_set_ids INTEGER[]`를 쓴다. 조인 테이블을 만들지 않는다.

숙제는 항상 통째로 읽고, "이 단어장을 쓰는 숙제 찾기" 같은 질의가 없다. 기존 퀴즈도
`/test/start?sets=1,2,3`처럼 id 목록을 받는다.

대가: 단어장이 지워지면 배열에 죽은 id가 남는다. 지금 앱에 단어장 삭제 경로가 없으므로
(서버에 `DELETE /wordsets` 라우트가 없다) 당장 문제가 되지 않는다. 조회할 때 서버가
실제 존재하는 단어장만 조인해 돌려주므로 죽은 id는 조용히 빠진다.

## 4. 데이터

```sql
CREATE TABLE IF NOT EXISTS homework (
  id SERIAL PRIMARY KEY,
  -- 이 숙제를 푸는 날. 시간대 없는 달력 날짜다 (3.3 참고).
  due_date DATE NOT NULL,
  word_set_ids INTEGER[] NOT NULL,
  -- 0이면 고른 단어장의 단어를 전부 낸다.
  question_count INTEGER NOT NULL DEFAULT 0,
  created_at BIGINT NOT NULL,
  -- NULL이면 아직 안 끝낸 숙제다.
  completed_at BIGINT,
  -- 어느 시험으로 끝냈는지. 부모 화면에서 결과로 넘어갈 때 쓴다.
  completed_group_id TEXT
);

CREATE INDEX IF NOT EXISTS idx_homework_due_date ON homework(due_date);
```

같은 날짜에 숙제를 여러 개 낼 수 있다(UNIQUE 제약을 두지 않는다). "A-B-B 20문제"와
"Unit12 10문제"를 같은 날 내는 것은 자연스러운 사용이고, 홈에는 카드 두 개로 뜬다.

## 5. 서버 API

모두 `/api` 아래, 기존 `server/routes.js`에 더한다.

### `GET /homework?from=YYYY-MM-DD&to=YYYY-MM-DD`

부모 화면용. 기간 안의 숙제를 날짜 오름차순으로 준다. 각 행에 단어장 제목과 현재 단어
수를 함께 돌려준다(죽은 id는 빠진다).

```json
[{ "id": 12, "dueDate": "2026-10-02", "wordSetIds": [13],
   "wordSets": [{ "id": 13, "title": "동사 3단변화 · A-B-B", "count": 40 }],
   "questionCount": 20, "completedAt": null, "completedGroupId": null }]
```

### `GET /homework/pending?today=YYYY-MM-DD`

아이 홈 화면용. **오늘 숙제**(`due_date = today`)와 **밀린 숙제**(`due_date < today`이고
`completed_at IS NULL`)를 돌려준다. 미래 숙제는 돌려주지 않는다. 오늘 숙제는 이미 끝냈어도
돌려준다 — 홈에 "오늘 숙제 다 했어요"를 보여주기 위해서다.

```json
{ "today": [ ...위와 같은 모양... ], "overdue": [ ... ] }
```

밀린 숙제는 **오래된 것부터** 준다. 밀린 지 오래된 것을 먼저 풀게 한다.

### `GET /homework/:id`

숙제 하나. 퀴즈 화면이 단어장 목록과 문제 수를 받아 바로 시작하는 데 쓴다.

### `POST /homework`

```json
{ "fromDate": "2026-10-02", "toDate": "2026-10-08",
  "wordSetIds": [13], "questionCount": 20 }
```

기간을 날짜로 펼쳐 한 트랜잭션에 넣는다. 만든 숙제들을 돌려준다.

검증: `wordSetIds`가 비어 있지 않을 것, `toDate >= fromDate`, 기간이 **92일 이하**일 것
(실수로 몇 년치를 넣는 것을 막는다), `questionCount >= 0`.

### `POST /homework/:id/complete`

```json
{ "groupId": "..." }
```

`completed_at`과 `completed_group_id`를 채운다. **이미 완료된 숙제면 아무것도 바꾸지 않고
성공으로 응답한다**(멱등). 아이가 같은 숙제를 또 다 맞혀도 처음 기록이 남는다.

### `DELETE /homework/:id`

한 행을 지운다. 완료된 숙제도 지울 수 있다.

## 6. 순수 함수 (`src/lib/homework.ts`)

화면과 서버 양쪽에서 쓰고, 단위 테스트로 고정한다.

```ts
/** "2026-10-02" 같은, 시간대에 흔들리지 않는 그 기기의 오늘 날짜. */
export function localDateString(d: Date = new Date()): string

/** 시작일~종료일을 날짜 문자열 목록으로 펼친다. 거꾸로 주면 빈 목록. */
export function expandDateRange(from: string, to: string): string[]

/** 배정 버튼에 쓸 "7일치"의 7. */
export function dayCount(from: string, to: string): number

/** 다음 날 날짜 문자열. 배정 후 날짜를 자동으로 넘길 때 쓴다. */
export function nextDate(date: string): string

/** "10월 2일 (목)" */
export function formatDueDate(date: string): string

export interface HomeworkSummary { id: number; dueDate: string; wordSets: {title: string}[]; questionCount: number; completedAt: number | null }

/** 숙제 한 건의 상태. 홈 카드의 색과 문구를 정한다. */
export type HomeworkState = 'today' | 'today-done' | 'overdue'
export function homeworkState(hw: HomeworkSummary, today: string): HomeworkState
```

`expandDateRange`는 **날짜 문자열끼리만 계산한다.** `Date`에 하루씩 더하면 서머타임이
있는 지역에서 하루가 겹치거나 빠진다. UTC 기준으로 더하고 다시 문자열로 만든다.

## 7. 부모 화면 `/admin`

가계부·OPIC이 쓰는 `AccessGate`를 그대로 감싼다. 같은 비밀번호다.

```
← 숙제 관리

숙제 내기
  단어장 고르기
    ☑ 동사 3단변화 · A-B-B   단어 40개
    ☐ Unit12 Earth & Nature  단어 50개
    ...
  기간    [2026-10-02]  ~  [2026-10-08]
  문제 수  (5) (10) (20) (전체)
  ┌─────────────────────────────┐
  │      7일치 숙제 내기          │
  └─────────────────────────────┘

배정된 숙제
  10/2 (목)  동사 3단변화 · A-B-B   20문제   완료 ✓   [삭제]
  10/3 (금)  동사 3단변화 · A-B-C   20문제   안 함    [삭제]
```

**배정하고 나면 날짜가 자동으로 다음 날로 넘어가고 단어장 선택이 풀린다.** 날마다 다른
단어장을 내는 것이 주된 사용법이라(월 A-B-B, 화 A-B-C, ...), 그 반복을 `체크 → 배정`
두 동작으로 줄인다. 같은 숙제를 일주일 내리 내려면 기간을 길게 잡고 한 번만 누르면 된다.

기본값: 기간은 오늘~오늘, 문제 수는 20.

"배정된 숙제" 목록은 **오늘부터 앞으로 4주치와 지난 2주치**를 보여준다. 전부 불러오면
시간이 갈수록 느려지고, 부모가 보고 싶은 것은 "곧 할 것"과 "최근에 밀린 것"이다.

단어장 목록은 `TestSelect.tsx`의 체크박스 목록과 생김새가 같다. 같은 모양의 목록이 두
화면에 생기므로 `src/components/WordSetPicker.tsx`로 빼고 양쪽이 쓴다.

## 8. 아이 홈 화면

숙제가 있으면 **지금 "테스트 시작하기"가 있는 가장 눈에 띄는 자리**를 숙제가 차지하고,
"테스트 시작하기"는 그 아래로 내려간다. 숙제가 없으면 지금 화면 그대로다.

| 상태 | 생김새 | 문구 |
|---|---|---|
| 오늘 숙제, 안 함 | 진한 초록(primary) | **오늘의 숙제** / 단어장 이름 · N문제 |
| 오늘 숙제, 완료 | 연한 초록 + 체크 | **오늘 숙제 다 했어요!** / 단어장 이름 |
| 밀린 숙제 | 주황(accent) | **밀린 숙제 · 10월 1일 (수)** / 단어장 이름 · N문제 |

밀린 숙제는 오래된 것부터 쌓아 보여준다. 완료된 오늘 숙제는 누르면 다시 풀 수 있지만
완료 기록은 그대로다.

**단어가 하나도 없는 숙제**(단어장이 비었거나 죽었다)는 흐리게 표시하고 누를 수 없게 한다.
문구는 "단어가 없어요". 아이가 눌렀는데 빈 시험이 뜨는 것보다 낫다.

홈 화면은 지금 `getHomeStats()` 하나만 부른다. 여기에 `getPendingHomework(today)`를 더한다.
숙제 불러오기가 실패해도 **홈의 나머지는 그대로 보여준다** — 숙제는 홈의 일부일 뿐이고,
서버가 깨어나는 중이라고 홈 전체가 막히면 안 된다.

## 9. 숙제를 눌렀을 때

새 경로 `/quiz/homework/:homeworkId`가 기존 `Quiz` 컴포넌트로 간다.

1. `GET /homework/:id`로 단어장 목록과 문제 수를 받는다
2. 그 단어장들의 단어를 모아 온다 (기존 여러 단어장 경로와 같다)
3. **설정 화면을 건너뛰고** 바로 문제를 낸다. 문제 수는 부모가 정한 값, 순서는 **항상 섞기**

순서를 항상 섞는 이유: 같은 단어장을 매일 배정했을 때 날마다 같은 순서로 같은 문제가
나오면 아이가 답을 외워버린다. 40개 단어장에서 20문제를 내면 날마다 다른 20개가 나온다.

**이어서 풀기**는 숙제별로 따로 저장한다. 지금은 단어장 id 목록을 열쇠로 쓰는데, 그러면
같은 단어장의 숙제와 자유 시험이 서로의 진행 상황을 덮어쓴다. 숙제는 `hw-12`를 열쇠로
쓴다.

완료 기록은 `finishRound`의 `isFinal`(틀린 단어 0) 지점에서 `POST /homework/:id/complete`를
보낸다. **이 요청이 실패해도 시험 결과 화면은 정상으로 보여준다** — 시험 기록 자체는 이미
저장됐고, 숙제 도장이 안 찍힌 것은 다시 풀면 복구된다. 결과 화면에 조용한 안내 한 줄을
남긴다.

결과 화면에서 숙제를 끝냈으면 "**오늘 숙제 끝!**" 한 줄을 더한다.

## 10. 오류와 경계

| 상황 | 동작 |
|---|---|
| 숙제의 단어장이 전부 지워졌다 | 홈 카드가 흐려지고 눌리지 않는다 ("단어가 없어요") |
| 문제 수가 단어 수보다 많다 | 기존 퀴즈와 같다 — 있는 단어만 낸다 |
| 같은 숙제를 두 번 다 맞혔다 | 완료 기록은 처음 것만 남는다 (멱등) |
| 숙제 불러오기 실패 | 홈의 나머지는 정상. 숙제 자리에만 조용한 안내 |
| 완료 기록 전송 실패 | 결과 화면은 정상. 숙제는 안 끝난 채 남는다 |
| 기간을 거꾸로 넣었다 | 배정 버튼이 비활성 ("종료일이 시작일보다 빠릅니다") |
| 기간이 92일을 넘는다 | 서버가 400으로 거절 |
| 아이가 숙제 말고 자유 시험으로 다 맞혔다 | 숙제는 완료되지 않는다 (3.2) |

## 11. 테스트

- **순수 함수** (`src/lib/homework.test.ts`): 기간 펼치기(하루, 여러 날, 거꾸로, 월을 넘김,
  윤년), `localDateString`이 시간대에 흔들리지 않는 것, 상태 분류(오늘/완료/밀림),
  `nextDate`가 월말·연말을 넘기는 것
- **서버 라우트**: 실제 DB에 배정하고 조회해 날짜별 행이 맞게 생기는지, 완료가 멱등인지,
  죽은 단어장 id가 조용히 빠지는지
- **화면** (Playwright): 배정 → 홈에 카드가 뜸 → 눌러서 바로 시작 → 다 맞히면 완료로 바뀜 →
  밀린 숙제가 남음. 390px와 1440px에서 가로 스크롤이 없을 것
- **회귀**: `TestSelect`의 단어장 목록을 공용 컴포넌트로 바꾸므로, 기존 "테스트 시작하기 →
  단어장 여러 개 선택 → 시험" 흐름이 그대로인지 확인한다. 숙제가 하나도 없을 때 홈 화면이
  지금과 똑같은지도 확인한다.
