# OPIC 스크립트 암기장 — 1단계(보면서 외우기) 설계

## 배경 및 목표

DirectorHome에 세 번째 서비스로 **OPIC 스크립트 암기장**을 추가한다. 사용자가 직접 정리해 둔
`2026 OPIC 2.xlsx`(주제별 사전 스크립트)를 폰과 PC에서 크게 읽으며 외우는 것이 목적이다.
시험을 앞두고 이동 중에 폰으로 보는 것이 주된 사용 상황이고, 집에서는 PC로 본다.

성공 기준은 "엑셀을 열지 않고 폰만으로 주제별 스크립트를 찾아 읽고, 어디까지 외웠는지
기록할 수 있다"이다.

기획은 사용자가 만든 디자인 캔버스(`OPIC 스크립트 암기장 기획`, 아트보드 5종: 기획서 본문,
모바일 홈/주제/스크립트, PC 3단)를 따른다. 이 문서는 그 기획을 구현 관점에서 확정한다.

## 범위

기획서는 3단계 구축을 제안하며, **이번 스펙은 1단계(보면서 외우기)만** 다룬다.

1단계에 포함되는 것:

- 엑셀 → Postgres 1회성 임포트(검수 목록 확인 후 확정)
- OPIC 전용 LNB와 세 화면: 주제 홈 · 주제 상세 · 스크립트 뷰어 (모바일/PC 반응형)
- 하이라이트 2종: 만능 패턴(파란 밑줄), 뜻·발음 주석 칩(노랑)
- 문항별 암기 상태 4단계 저장(미설정/아직 부족/그럭저럭/암기완료)
- 가계부와 같은 비밀번호 세션 공유

### 목표가 아닌 것 (Non-goals)

- **음성 재생 일체** — 에바(여)/답변(남) TTS, 배속, 문장 싱크 하이라이트는 2단계.
  다만 구현 방식은 **Web Speech API(브라우저 내장, 무료)** 로 확정했다. 서버 작업과 비용이
  없으므로 2단계는 기획서가 가정한 클라우드 TTS안보다 훨씬 작다.
- 첫 글자 힌트 / 가리기 모드, 복습함 연속 재생, 형광 직접 편집, 주제별 암기율 통계 — 3단계.
  **눌러도 아무 일이 없는 컨트롤은 그리지 않는다.** 기획서 화면에 있는 보기 방식 토글,
  LNB의 복습함·음성·표시 설정 항목은 해당 기능이 생기는 단계에 함께 넣는다.
- 가계부 화면 변경. OPIC은 자체 LNB를 갖고 가계부의 기존 사이드바는 건드리지 않는다.
- 다중 사용자. 기존 서비스와 같이 단일 사용자 전제이며 암기 상태에 사용자 구분을 두지 않는다.

## 1. 아키텍처

기존 저장소를 그대로 확장한다. 새 React 라우트(`/opic/*`), 새 Express API(`/api/opic/*`),
새 Postgres 테이블을 추가하며 배포는 지금의 Cloud Run 단일 서비스를 유지한다.

원본 엑셀은 저장소에 커밋하지 않는다. 임포트 스크립트가 로컬에서 엑셀을 읽어 Postgres에
넣고, 앱은 DB만 바라본다.

## 2. 접근 권한

`src/components/HouseholdGate.tsx`를 **`AccessGate.tsx`로 이름만 바꾸고** 가계부와 OPIC이
함께 쓴다. 파일 이름 외의 동작은 그대로다:

- 같은 `localStorage` 키 `hh_access_until`, 같은 만료(30일)
- 같은 검증 엔드포인트 `POST /api/expense/verify-password`

따라서 가계부에서 이미 로그인했다면 OPIC은 비밀번호 없이 바로 열리고, 그 반대도 같다.
`HouseholdGate`를 참조하는 3개 화면(`Household`, `HouseholdStats`, `HouseholdCategories`)의
import를 함께 고친다. 호환용 재수출(shim)은 두지 않는다.

비밀번호 검증 API는 가계부 것을 그대로 재사용한다. OPIC 전용 엔드포인트를 새로 만들지 않는다.

## 3. 데이터 모델

가계부 테이블과 같은 명명·타입 관례를 따른다(`created_at`/`updated_at`은 epoch 밀리초 `bigint`).

```sql
CREATE TABLE opic_topics (
  id            SERIAL PRIMARY KEY,
  name          TEXT NOT NULL,          -- 'Bar', 'Movie', '신문'  (★ 제거한 이름)
  sheet_name    TEXT NOT NULL UNIQUE,   -- 'Bar★★★'  원본 시트명, 재임포트 대조용
  stars         INT  NOT NULL,          -- 시트명의 ★ 개수 = 빈출도 3/2/1
  kind          TEXT NOT NULL,          -- 'topic' | 'roleplay'
  display_order INT  NOT NULL,
  created_at    BIGINT NOT NULL
);

CREATE TABLE opic_questions (
  id            SERIAL PRIMARY KEY,
  topic_id      INT  NOT NULL REFERENCES opic_topics(id) ON DELETE CASCADE,
  set_label     TEXT,                   -- '1set' | '14번' | 'ROLE PLAY' | null
  seq           INT  NOT NULL,          -- 주제 안에서의 순서
  level         TEXT,                   -- 'Int' | 'Adv' | null
  title_ko      TEXT NOT NULL,          -- 대표 한글 제목
  alt_titles    TEXT[] NOT NULL DEFAULT '{}',  -- 같은 답변을 쓰는 유사 질문들
  importance    INT  NOT NULL DEFAULT 0,       -- 제목 끝 ★ 개수(0~5)
  question_en   TEXT NOT NULL,          -- 에바의 영어 질문(여러 줄)
  answer_en     TEXT NOT NULL,          -- 답변 전문(줄바꿈 = 문장, 빈 줄 = 문단)
  source_ref    TEXT NOT NULL,          -- 'Bar★★★!C4'  추적용
  answer_hash   TEXT NOT NULL,          -- 답변 본문 정규화 해시(중복 묶기·재임포트 대조)
  created_at    BIGINT NOT NULL
);
CREATE INDEX opic_questions_topic_idx ON opic_questions (topic_id, seq);
CREATE INDEX opic_questions_hash_idx  ON opic_questions (answer_hash);

CREATE TABLE opic_status (
  answer_hash   TEXT PRIMARY KEY,       -- 문항 id가 아니라 답변 해시에 붙인다(아래 설명)
  state         TEXT NOT NULL,          -- 'weak' | 'ok' | 'done'
  updated_at    BIGINT NOT NULL
);

CREATE TABLE opic_patterns (
  text          TEXT PRIMARY KEY,       -- 만능 패턴 문장 원문
  topic_count   INT NOT NULL,           -- 몇 개 주제에 걸쳐 나오는지
  occurrences   INT NOT NULL
);
```

**문장을 별도 테이블로 두지 않는다.** 엑셀이 이미 한 줄 = 한 문장이므로 `answer_en`을
줄 단위로 나눠 화면에서 쓴다. 암기 상태가 문항 단위라 문장 행이 필요 없고, 문장 편집
기능은 3단계에 있다.

**암기 상태를 `answer_hash`에 붙이는 이유.** 검증 결과 답변 본문이 완전히 같은 문항이
**63종 151행** 있다(예: Movie 1set과 2set의 '최근 영화관' 답변). 기획서가 요구한 "본문이
같으면 하나의 문항으로 묶어 암기 상태 공유"가 해시 키로 자연히 달성되고, 엑셀을 고쳐
재임포트해 `opic_questions.id`가 바뀌어도 상태가 유지된다.

### 원래 요청과의 차이

최초 요청은 "암기된 **문장**은 토글"이었으나 기획서는 "**문항**마다 3단계"로 정리되어 있다.
기획서를 따라 **문항 단위**로 구현한다. 문장 단위가 필요해지면 3단계에서 다룬다.

## 4. 엑셀 임포트

`scripts/import-opic.mjs`(1회성, 가계부 과거 데이터 이전 스크립트와 같은 자리). 로컬에서
엑셀 경로와 `DATABASE_URL`을 받아 실행한다.

### 4.1 시트 분류

31개 시트 중:

- `서베이` — 내용 없음. 건너뛴다.
- `Roleplay`, `Roleplay1` — `kind='roleplay'`. 아래 4.3 참고.
- 나머지 28개 — `kind='topic'`. 시트명 끝 ★ 개수가 빈출도이고, ★를 뗀 앞부분이 주제명이다.

검증 실측: 주제 시트 30개(롤플레이 2종 포함), 문항 행 **358개**.

### 4.2 주제 시트 파싱

한 행이 한 문항이며 A·B·C열을 쓴다.

- **A열** — 세트 라벨. 값이 없으면 위 행의 세트를 잇는다. `ROLE PLAY ...`만 있고 B·C가 빈
  행은 구분선이므로 이후 행의 세트를 `ROLE PLAY`로 바꾼다. 실측 라벨은
  `1set`~`7set`, `11번`~`15번`이며 **`1Set`처럼 대소문자가 섞인 값 3건과 `7.0`/`8.0`처럼
  숫자로 저장된 값 2건**이 있다. 소문자 정규화하고 `7.0` → `7번`으로 바꾼다.

- **B열** — 한글 제목 줄들 다음에 영어 질문이 온다. **경계는 "한글이 없고 영문자로 시작하는
  첫 줄"**이다. 빈 줄로 나누는 규칙은 358행 중 104행에서 깨지므로 쓰지 않는다
  (`Movie★★★` 등은 한 줄 바꿈만으로 붙어 있다).
  - 경계 앞: 줄마다 `[Int]`/`[Adv]`와 끝의 ★를 떼어 `level`·`importance`를 얻고 남은 글을
    제목으로 삼는다. 첫 줄이 `title_ko`, 나머지는 `alt_titles`.
  - 경계 뒤: `question_en`.
  - 경계를 찾지 못한 행은 **검수 목록**으로 올리고 임포트하지 않는다.

- **C열** — `answer_en`에 원문 그대로 넣는다. 줄바꿈과 빈 줄을 보존한다.

### 4.3 롤플레이 시트

`Roleplay`는 B열이 `영업점메시지시작` 같은 짧은 라벨이고 C열이 영어 본문인 **패턴 조각 모음**
이라 Q&A 구조가 아니다. 이 두 시트는 `kind='roleplay'`로 넣되 `title_ko`에 라벨을,
`answer_en`에 본문을 넣고 `question_en`은 빈 문자열로 둔다. 화면에서는 질문 카드 없이
본문만 보여준다.

### 4.4 만능 패턴 탐지

모든 답변을 줄 단위로 모아 **서로 다른 주제 3개 이상에서 반복되는 문장**을 `opic_patterns`에
넣는다. 12자 이하 줄은 제외한다. 실측 **92문장**이 잡히며 최다 문장
(`Give me a call when you get this. Thanks.`)은 15개 주제에 등장한다.

### 4.5 검수 목록 먼저

DB에 쓰기 전에 다음을 출력하고 사용자 확인을 받는다. 확인 전에는 아무것도 쓰지 않는다.

- B열 경계를 찾지 못한 행 (시트·행번호·앞부분)
- 빈 시트(`서베이`)
- 시트 머리글과 시트명이 다른 경우 — 기획서가 지적한 `Hotel★★` 시트의 머리글이 `Bank ★★`이고
  질문 일부도 은행 문장인 문제
- 시트명 오타 추정(`Heath` → `Health`)
- 주제·문항·패턴 건수 요약

재임포트는 `opic_topics`/`opic_questions`를 비우고 다시 넣되 `opic_status`와 `opic_patterns`는
건드리지 않는다. 상태는 `answer_hash`로 다시 붙는다.

## 5. 하이라이트

1단계는 **두 종류만** 구현한다.

**만능 패턴(파란 밑줄)** — 화면이 `opic_patterns` 목록을 한 번 받아, 답변의 각 줄이 목록에
정확히 일치하면 밑줄을 준다. 데이터로 계산되므로 오탐이 없다.

**주석 칩(노랑)** — 답변 안의 `(한글이 포함된 괄호)`를 본문에서 떼어 그 자리에 작은 칩으로
보여준다. 실측 **230개**가 있으며 성격이 섞여 있다: 줄 맨 앞의 분류 라벨(`(종류)`,
`(가격)`), 단어 뜻(`(출근길에)`), 발음(`(아웃릿츠)`), 문장 전체 번역
(`(많은 변화 발전을 해왔다.)`).

**어느 영어 표현에 붙는 주석인지는 추측하지 않는다.** 엑셀에 그 정보가 없어, 추측하면 틀린
강조를 만든다. 그 자리에 칩으로 두면 읽는 사람이 앞의 표현과 자연히 잇는다. 표현 범위를
직접 지정하는 기능은 3단계다. 다만 다음 두 가지는 규칙으로 구분한다:

- 줄 맨 앞에 오는 괄호는 **분류 라벨**로 보고 칩 대신 줄 앞 작은 머리표로 보여준다.
- `(디플로메틱,외교)`처럼 쉼표로 둘로 나뉘면 앞을 발음, 뒤를 뜻으로 갈라 칩 두 개로 만든다.

발음 주의(주황 점선)는 뜻/발음 자동 구분이 신뢰할 수준이 아니라 1단계에서 제외한다.

## 6. API

모두 `/api/opic` 아래에 두고 기존 `server/routes.js`에 추가한다.

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/opic/topics` | 주제 목록. 문항 수와 상태별 집계(done/ok/weak/미설정) 포함 |
| GET | `/api/opic/topics/:id/questions` | 해당 주제의 문항 목록(답변 본문 제외, 상태 포함) |
| GET | `/api/opic/questions/:id` | 문항 하나의 전체(질문·답변 본문 포함) |
| PUT | `/api/opic/status` | `{ answerHash, state }` 저장. `state: null`이면 미설정으로 삭제 |
| GET | `/api/opic/patterns` | 만능 패턴 문장 목록 |

주제 목록의 상태 집계는 `opic_questions`를 `answer_hash`로 `opic_status`에 조인해 센다.
답변 본문은 목록 응답에 넣지 않는다(358행 약 20만 자).

## 7. 화면

경로는 세 개다.

- `/opic` — 주제 홈
- `/opic/t/:topicId` — 주제 상세
- `/opic/t/:topicId/q/:questionId` — 스크립트 뷰어

PC(≥1024px)는 기획서대로 **한 화면에 3단**을 놓는다. 세 경로 모두 같은 3단 레이아웃을
쓰되 선택된 것이 없으면 해당 단이 빈 상태를 보여준다. 모바일은 같은 경로가 각각 한 화면씩만
보여준다(홈 → 상세 → 뷰어). 뒤로가기는 한 단계씩 거슬러 올라간다.

### 7.1 공통 셸

OPIC 전용 LNB를 새로 만든다(`OpicNav`). 기획서의 검정 LNB(`#1A1D26`, 232px)를 따르고
**1단계에서는 동작하는 항목만** 둔다 — 가계부(`/household`로 이동)와 OPIC(주제별 스크립트).
복습함과 음성·표시 설정은 그 기능이 생기는 단계에 추가한다. 모바일은 가계부와 같은 방식으로
상단 바 + 하단 탭바를 쓴다.

### 7.2 디자인 토큰

OPIC은 기획서의 자체 색을 쓴다. 가계부의 `--color-hh-*`와 섞지 않도록 `--color-op-*`로
`src/index.css`의 `@theme`에 추가한다: 바탕 `#F6F4EF`, 먹 `#1A1D26`, 강조 남색 `#3346C8`,
에바 자주 `#9A3B6E`, 테두리 `#E4E0D6`, 패턴 배경 `#E6E9FB`, 형광 `#FFE27A`.

상태 3색은 초록 `#15803D`(암기완료) · 황토 `#D69E2E`(그럭저럭) · 주황 `#E0662B`(아직 부족)
이며 명도가 서로 달라 색약에서도 구분된다. 색만으로 뜻을 전하지 않도록 **항상 글자를 함께**
표시한다.

본문 영문 스크립트는 **Source Serif 4**를 쓴다(모바일 20px · PC 22px, 줄간격 1.75).
UI 글꼴은 앱 전체가 쓰는 IBM Plex Sans KR을 그대로 쓴다. Source Serif 4는 `index.html`의
Google Fonts 링크에 추가한다.

### 7.3 주제 홈

전체 진도 요약(상태별 문항 수), 빈출도 필터(★★★/★★/★/전체), 주제 카드 격자.
카드에는 주제명·★·문항 수·3색 진도 바를 둔다. 롤플레이는 별도 구획으로 내린다.

### 7.4 주제 상세

주제 머리(이름·★·문항 수·3색 진도 바), 세트 탭, 문항 카드 목록. 카드에는 순번·Int/Adv·
중요도 ★·한글 제목·암기 상태 칩을 둔다.

### 7.5 스크립트 뷰어

위에서 아래로: 에바 질문 카드(자주색, 한글 제목 + 유사 질문 칩 + 영어 질문), 암기 상태
3칸 토글, 답변 본문. (보기 방식 토글은 힌트·가리기가 생기는 3단계에 함께 들어간다.)

답변 본문은 줄 단위로 렌더한다. 빈 줄은 문단 간격이 된다. 각 줄에 만능 패턴 밑줄과 주석
칩을 적용한다. 글자 크기 A−/A+ 3단계를 두고 선택은 `localStorage`에 남긴다(기기별 취향이라
서버에 두지 않는다).

하단에 이전/다음 문항 이동을 둔다. 2단계에서 이 자리가 재생 바가 된다.

## 8. 에러 처리

- 임포트 스크립트: 검수에서 걸린 행은 건너뛰고 목록에 남긴다. DB 쓰기는 한 트랜잭션으로
  묶어 중간 실패 시 통째로 되돌린다.
- 화면: 가계부와 같은 `Loading` / `LoadError` 컴포넌트를 재사용하고 재시도 버튼을 둔다.
- 상태 저장 실패: 화면의 토글을 이전 값으로 되돌리고 짧은 안내를 띄운다.
- 없는 주제·문항 id: 주제 홈으로 보낸다.

## 9. 테스트

순수 함수를 vitest로 덮는다(`src/lib/opicParse.test.ts`). 파서를 `src/lib/`에 두어
임포트 스크립트와 테스트가 같은 코드를 쓴다.

- B열 경계 찾기 — 빈 줄로 나뉜 경우, 한 줄 바꿈만 있는 경우, 경계가 없는 경우
- 제목에서 `[Int]`/`[Adv]`와 ★ 분리, 유사 질문 여러 줄
- 세트 라벨 정규화(`1Set`→`1set`, `7.0`→`7번`, 빈 값은 앞 세트 잇기)
- 시트명에서 주제명과 ★ 개수 분리
- 괄호 주석 분리 — 줄 맨 앞 라벨, 쉼표형(발음,뜻), 일반 뜻, 괄호 없는 줄
- 만능 패턴 매칭
- 답변 정규화 해시가 공백 차이를 무시하고 같은 본문을 같게 보는지

화면은 임포트한 실제 데이터로 로컬에서 확인한다(모바일 390px, PC 1440px).
